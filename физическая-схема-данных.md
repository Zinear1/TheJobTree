# Физическая схема данных

## Выбор СУБД и общие параметры реализации

В качестве системы управления базами данных выбрана **PostgreSQL** (версия 14+). Выбор обусловлен строгой поддержкой стандарта SQL, развитой системой ограничений целостности (`CHECK`, `UNIQUE`, каскадные правила `ON DELETE`), поддержкой процедурного языка **PL/pgSQL** (для триггеров и транзакционных функций), а также стабильной интеграцией с веб-фреймворком **Flask** через драйвер `psycopg2`.

* **Имя базы данных:** `thejobtree`
* **Схема по умолчанию:** `public`
* **Кодировка:** `UTF-8`
* **Генерация первичных ключей:** стандартный для PostgreSQL механизм `INT GENERATED BY DEFAULT AS IDENTITY`.
* **DDL-скрипт создания структуры:** [`создание-базы-данных.sql`](создание-базы-данных.sql)
* **Скрипт тестового наполнения:** [`демонстрационные-данные.sql`](демонстрационные-данные.sql)

## Стратегия ссылочной целостности (`ON DELETE`)

* `ON DELETE CASCADE` применяется для зависимых данных (объявления удалённого работодателя, связи в `ad_skills` и `user_skills`, отклики и чаты при удалении объявления, сообщения при удалении чата).
* `ON DELETE SET NULL` используется там, где потеря связанной записи не должна уничтожать основную сущность (`ads.worker_id` при удалении аккаунта исполнителя, `categories.parent_id` и `skills.category_id` при удалении категории).
* `ON DELETE RESTRICT` установлен на `ads.category_id`, чтобы случайно не удалить категорию, в которой уже есть активные или архивные объявления.

## Система индексов

Помимо автоматических B-Tree индексов, создаваемых PostgreSQL для всех `PRIMARY KEY` и `UNIQUE` ограничений, определены 10 пользовательских B-Tree индексов под основные запросы веб-приложения:

| Индекс | Таблица и столбцы | Назначение |
| :--- | :--- | :--- |
| `idx_ads_status_city` | `ads (status, city)` | Быстрая выборка активных объявлений в выбранном городе на главной ленте |
| `idx_ads_category` | `ads (category_id)` | Фильтрация ленты объявлений по категориям и ускорение `JOIN` с `categories` |
| `idx_ads_employer` | `ads (employer_id)` | Вывод вкладки созданных объявлений в профиле работодателя |
| `idx_ads_worker` | `ads (worker_id)` | Вывод объявлений «в работе» и «выполнено» в профиле исполнителя |
| `idx_ads_budget` | `ads (budget)` | Фильтрация по диапазону оплаты (`BETWEEN`, `>=`) и сортировка по бюджету |
| `idx_ad_skills_skill` | `ad_skills (skill_id)` | Ускорение фильтрации объявлений по выбранным софт-скиллам и навыкам |
| `idx_responses_ad` | `responses (ad_id)` | Загрузка списка откликов в карточке объявления работодателя |
| `idx_responses_user` | `responses (applicant_id)` | Отображение раздела «Мои отклики» в личном кабинете соискателя |
| `idx_messages_chat_time` | `messages (chat_id, sent_at)` | Получение истории переписки конкретного чата в хронологическом порядке |
| `idx_reviews_target` | `reviews (target_id)` | Выборка отзывов о пользователе и быстрый расчёт рейтинга в `user_ratings` |

## Серверная логика на уровне базы данных

Часть критически важных правил целостности вынесена непосредственно в PostgreSQL, чтобы бизнес-логика соблюдалась независимо от того, как поступают запросы (через Flask или напрямую из SQL-консоли):

1. **Триггер `trg_create_chat_on_response` (функция `create_chat_on_response()`):**
   * срабатывает `AFTER INSERT ON responses`;
   * проверяет, что `applicant_id` не совпадает с `employer_id` объявления (при совпадении выбрасывает исключение и откатывает вставку);
   * автоматически создаёт запись в таблице `chats` для нового отклика.
2. **Хранимая функция `accept_response(p_response_id INT)`:**
   * выполняется атомарно в рамках транзакции при нажатии кнопки «Утвердить исполнителя»;
   * переводит выбранный отклик в статус `'принят'`, отклоняет все остальные ожидающие отклики на это объявление (`'отклонен'`), записывает `worker_id` в таблицу `ads` и переводит объявление в статус `'в работе'`.
3. **Представление `user_ratings`:**
   * выполняет `LEFT JOIN` таблиц `users` и `reviews` с группировкой по пользователю;
   * возвращает `reviews_count` и `avg_rating` (округлённое до двух знаков среднее арифметическое, либо `0.00`, если отзывов ещё нет).
